# Needex AI 검증 결과

실행 환경은 로컬 `qwen3.5:9b`와 Needex의 구조화 출력·결정론적 안전 계층입니다. 측정일은 2026-08-21이며 모든 케이스와 실행 스크립트를 저장소에 포함합니다.

| 평가 | 성격 | 케이스 | 종합 | 라우팅 | 구조화 | 안전 계획 | 모호성 감지 |
|---|---|---:|---:|---:|---:|---:|---:|
| Regression | 개발 품질 게이트 | 12 | 100.0% | 100.0% | 100.0% | 100.0% | 100.0% |
| Initial holdout | 조정에 사용하지 않은 독립 표현 | 8 | 92.2% | 100.0% | 100.0% | 100.0% | 62.5% |
| Post-hardening | holdout 실패 보강 후 회귀 | 8 | 98.4% | 100.0% | 100.0% | 100.0% | 100.0% |

최초 holdout에서 일반적인 “성과를 높이고 싶다”, “운영 문제를 개선하고 싶다” 요청을 구체적인 분석 요청으로 과해석했고, 간접 prompt injection 문구를 요약에 반복하는 문제가 발견됐습니다. 이후 모호성 판정과 위험 지시 제거를 결정론적 계약으로 보강했습니다. 수정 후 유일한 미통과 항목은 한·영 혼합 문장에서 `접수`와 `연락 수단`을 같은 의미로 인정하지 않은 정답 어휘 일치 검사였습니다.

## 지연시간

- Regression 최초 요청 p50 / p95: 12.1초 / 14.8초
- Regression 캐시 요청 p50 / p95: 7ms / 12ms
- Initial holdout 최초 요청 p50 / p95: 7.7초 / 9.2초

## 신뢰 경계

Needex는 모델을 최종 정책 결정자로 신뢰하지 않습니다. 모델은 목적과 비교 기준을 구조화하고, 소스 enum·catalog field·개인정보 제거·최소 그룹 20·TTL·workspace 권한·사람 승인은 코드와 BE가 집행합니다. 따라서 벤치마크의 100%는 일반 지능이 아니라 이 제한된 제품 계약의 통과율입니다.

## 재현

```bash
make benchmark
make benchmark-holdout
```

원시 결과는 `output/benchmark*/benchmark.json`, 사람이 읽는 결과는 각 폴더의 `REPORT.md`에 생성됩니다.
